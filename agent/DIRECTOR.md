# Zeno Director

The agent chooses the edit. The engine measures, renders and verifies. Follow the active user's instructions and the owner's visual rules in `AGENTS.md` / `CLAUDE.md`.

1. Queue one or multiple videos back-to-back in a single chat session (up to `1M` / `1,000,000` context tokens) while keeping Notion and Meta connectors enabled; each video's `--inspect` starts an isolated per-video cost/telemetry window (`INR 40` / `24` requests). Inputs are a local footage folder, one script `?tab=...` (or local path), and the exact Notion name (read from Notion when a Notion card/queue is shared). Use supplied inputs immediately.
2. Run `.venv/bin/python scripts/zeno.py --inspect <footage> --script <script> --name "<name>" --auto-plan --compact` (Windows `.venv\Scripts\python.exe`; add `--style <name>` when known). This runs live preflight, inspects/reuses clips, runs Zeno's isolated 1-call subscription planner (`claude -p` or `codex exec` using the editor's existing subscription with zero connector/history re-read overhead, typically `20k–55k` total tokens), checks `--check-plan`, and prints the concrete plan Pitch Card. If inputs are missing, run `--preflight --compact` and ask for them. Never use `--skip-preflight`.
3. Do NOT re-open `editing_packet.md`, `line_map.md`, `facts.md`, `EDIT_RULES.md`, or `clip_sheet_*.jpg` in the outer chat when `--auto-plan` already passed `[PLAN PASS]`. Open `editing_packet.md` and `clip_sheet_*.jpg` once only if manual planning is needed, or fetch targeted line evidence via `<PY> scripts/edit_packet.py <project> --line L12` (and `styles/<name>/SKILL.md` once if requested).
4. Before manual planning or correction rounds, check `<PY> scripts/cost_control.py <project>`; if blocked, save work and stop further model rounds. When planning or fixing manually, write `script_analysis.md` and the complete `plan.edl`, then run `--check-plan` in the same command. Fix actual blockers; voice/line uncertainty needs targeted `edit_packet.py` evidence, not repeated identical checks.
5. Show the concrete plan and obtain Yes/No once, unless the user explicitly pre-authorized queued rendering across a batch of videos. Execute `<PY> scripts/zeno.py --execute <plan> --square --compact` as one single blocking/completion-notified run — never poll `write_stdin` or progress files in a loop.
6. `verify.py` checks both 9:16 and 1:1 Square framing and builds a single compact `review_sheet.jpg` automatically; never write custom FFmpeg/Python frame-extraction scripts. Inspect `review_sheet.jpg` once (or on failure), fix failed checks, and deliver exports with the saved per-video token/cost report. Record human feedback verbatim with `--feedback` before revisions. Development belongs in a separate chat; never debug Zeno itself in a benchmark edit.

Default `--auto-plan` uses the editor's existing subscription with no API key (`< 1,00,000` tokens/video). For the optional bounded Sol API planner (`LOW_COST_WORKFLOW.md`), separate API billing is required and must be chosen explicitly.

Open a concept only for its relevant problem: script access (01), intake (02), styles (03), reference learning (04), text (05), telemetry (06), alignment (07), preproduction (08), team learning (09). No code-development manuals during ordinary editing.
