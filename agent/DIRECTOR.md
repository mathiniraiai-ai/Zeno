# Zeno Director

The agent chooses the edit. The engine measures, renders and verifies. Follow the active user's instructions and the owner's visual rules in `AGENTS.md` / `CLAUDE.md`.

Editorial quality comes first. Automatic completion still requires review of saved verification and `review_sheet.jpg` before delivery. Automatic edits may share this chat through isolated `--auto-plan`; fresh-chat guidance below applies to manual planning. Host usage and project budgets still count. A plan pass is not editorial approval. Preserve complete requested style rules, emotional intent and required corrections.

1. **Fresh Chat & Inputs**: Start one fresh chat per video. `.claude/settings.json` loads the Zeno server only. Inputs are a local footage folder, script `?tab=...` (or local path), and exact Notion name supplied by the editor; never invent or re-ask supplied inputs. Each `--inspect` isolates reporting, not the persistent project request budget. `[PLANNER STOPPED]` means report the `[BLOCKED]` lines and ask the editor how to proceed; do not retry, plan by hand or reread packets. A new chat does not replenish the project's budget.
2. **Turn 1 — Automatic Planning**: Run `.venv/bin/python scripts/zeno.py --inspect <footage> --script <script> --name "<name>" --auto-plan --compact` (Windows `.venv\Scripts\python.exe`; add `--style <name>` when known). This runs live preflight, reuses measured clips, makes one isolated planning request and at most one targeted correction per invocation, checks the plan, prints the Pitch Card, and automatically renders 9:16 + 1:1 Square without asking Yes/No. Subscription planners use `claude -p` or `codex exec`; overhead and billed usage must be measured. If inputs are missing, run `--preflight --compact` and ask for them. Never use `--skip-preflight`. On `[PLAN PASS]`, do NOT open packets/sheets/rules; deliver outputs + token report.
3. **Manual Fallback (4–5 Turns Max)**: Only when explicitly returned before planning, or authorized by the editor; never to bypass a planner or budget stop.
   - **Turn 2**: Read `editing_packet_p*.md` (or `editing_packet.md`) + ALL `clip_sheet_*.jpg` in ONE parallel batch (and `styles/<name>/SKILL.md` once only if a requested style needs it).
   - **Turn 3**: Write `script_analysis.md` and `plan.edl` (plus `decisions.txt` if needed) in ONE parallel batch.
   - **Turn 4**: Never ask Yes/No before rendering (unless the user explicitly requested `--no-auto-render` / plan-only review). Run ONE combined check+render command: `<PY> scripts/zeno.py --execute <plan> --square --compact` (no separate `cost_control.py` + `--check-plan` + `--execute` roundtrips unless `--check-plan` is explicitly needed or the plan fails!). If a command backgrounds, **END TURN immediately** and wait for system completion notification — NEVER poll `manage_task`, `write_stdin`, `send_input`, or progress/log files!
   - **Turn 5**: `verify.py` checks both 9:16 and 1:1 Square framing and builds a single compact `review_sheet.jpg` automatically; never write custom FFmpeg/Python frame-extraction scripts. Read `review_sheet.jpg` ONCE (unless verify fails) and present deliverables + saved per-video token/cost report.
4. **Targeted Fixes & Cost Guardrails**: Record human feedback verbatim with `--feedback "<words>" --plan <plan>` before revisions. For failed checks or targeted revisions, check `<PY> scripts/cost_control.py <project>` if correction rounds repeat (stop model work if blocked, save work, and explain), fetch only affected line evidence via `<PY> scripts/edit_packet.py <project> --line L12`, fix actual blockers, and run `--check-plan` before `--execute`. Development belongs in a separate chat; never debug Zeno itself in a benchmark edit.
5. **`[DO NOT]` During Edits**: NEVER open `agent/REFERENCE.md`, `CONCEPT.md`, `agent/EDIT_RULES.md`, `agent/FORMATS.md`, `scripts/*.py`, `clip_caches.json`, `facts.md`, `line_map.md`, `ffprobe`, or `dir`/`Get-ChildItem`/`ls` (`editing_packet.md` already holds syntax card, raw footage inventory, unmatched line diagnostics, and all words/candidates/rules).

**Limits**: 2 planner calls per invocation; 8 managed requests over the saved project's lifetime; at most 2 full-context requests with a combined 100,000 conservative input reserve; targeted corrections at most 24,000 UTF-8 bytes. Preserve `request_budget.sqlite3` and pending-call records. Pending/unknown managed-call usage stops further dispatch. Host checkpoints are 8 requests and 100,000-token starting context; the model cost estimate checkpoint is INR 40. These safeguards cannot cap the surrounding chat app or provider account, and the reserve is not a guarantee of billed total/cache tokens. See `LOW_COST_WORKFLOW.md` for full scope.

Default `--auto-plan` uses the editor's existing subscription with no API key. The optional Sol API planner requires explicit opt-in and separate API billing. Report uncached input, cache reads/writes, output, combined total, measured requests, elapsed time, transcription reuse and unknowns; API-equivalent costs are estimates, not invoices. Four to six total calls is a workflow aim, not a guarantee.

Never open `CONCEPT.md` or code-development manuals during ordinary edits; only outside active edit runs, consult a specific concept if needed for standalone setup/troubleshooting: script access (01), intake (02), styles (03), reference learning (04), text (05), telemetry (06), alignment (07), preproduction (08), team learning (09).
